# Browser with Playwright (rule M-12)

How an sdd-salesforce project sees and tests its UI. The rule is in the `sdd-method` skill (section "Browser"); here,
the setup, the limits and the Salesforce gotchas.

## Setup
- **`.mcp.json` of the project,** generated by `sdd-bootstrap` when the user says they will test in the browser: the
  server `playwright` runs `npx -y @playwright/mcp@<version> --browser chromium --user-data-dir .playwright/profile
  --output-dir .playwright/output`. The version is the one pinned in the catalog (`skills-by-area.json`,
  `browser.version`). `.playwright/` is not versioned.
- **Chromium:** each version of `@playwright/mcp` needs its own revision. If it is missing, `check-environment.py` gives
  the command: `npx -y @playwright/mcp@<version> install-browser chromium --no-shell`. It downloads Chromium from
  Playwright's CDN: say so and run it only with the user's OK.
- **Prerequisites:** `node` and `npx`.
- **What only the user does:** approve the project's MCP the first time Claude Code offers it, open a new session in
  the project (the MCP is loaded when a session starts, so it is not in the bootstrap session) and log in to the org
  once in the Chromium window, which opens visible. The cookies stay in `.playwright/profile`, only for this project.
- **An older project** (without `.mcp.json`): `sdd-bootstrap` with `--add-missing` creates it without touching the
  rest.

## Use
- **Only the project's org.** The browser guard (`hooks/browser_guard.py`) denies navigating to the host of another
  Salesforce org (My Domain, Lightning, Setup, sites, Visualforce, files and content, Experience Builder, messaging and
  micro-apps: `*.my.salesforce.com`, `*.lightning.force.com`, `*.my.salesforce-setup.com`, `*.my.site.com`,
  `*.salesforce-sites.com`, `*.salesforce-experience.com`, `*.vf.force.com`, `*.documentforce.com`,
  `*.salesforce.app`, `*.force.com`…) whose My Domain is not the project's, which `check-environment.py --query-org`
  stores in the inventory. A sandbox is its own org: `acme--uat` is not `acme`. It reads the literal URLs of the
  tool's input, also in the file that `browser_run_code_unsafe` names. While the My Domain is not in the inventory, it
  **asks** before opening any org host. It lets through the project's org, `login.salesforce.com`,
  `test.salesforce.com`, the official documentation, `localhost` and public websites. It does not see the navigation
  that a click causes: check where you are with a snapshot.
- **Evidence:** in the step report, under `## Verification cases`, what was done and what was seen for each AC with
  `browser check`; the screenshots that prove it, in `docs/delivery-plan/evidence/<step>/`. Only synthetic data on
  screen.
- **Never** click an irreversible setting in Setup without the approver's OK (M-11), and never type a password.
- Take a snapshot before acting: the tools act on the elements of the latest snapshot.

## Salesforce gotchas
- **Iframes from another origin** (Setup pages, in `*.my.salesforce-setup.com`, and micro-apps, in `*.salesforce.app`)
  are not in the snapshot. Read them with code: `page.frames().find(f => f.url().includes('salesforce-setup.com'))`.
- **SLDS radio buttons:** the input is hidden; click the label.
- **"Log in as" a user:** the `Login` button is inside the iframe of the user's detail page in Setup.
- **Logging in as an Experience user:** the button uses
  `/servlet/servlet.su?oid=<org15>&sunetworkid=<0DB15>&sunetworkuserid=<00515>`, without a token. To leave,
  `/<prefix>/secur/logout.jsp` on the site's domain, which takes you back to the admin's session.
- **Lightning is slow to paint:** wait for a visible text of the page (`browser_wait_for`) before the snapshot.
